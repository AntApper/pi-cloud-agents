## Changes
- Pagination: new `core/aws/paginate.ts` (`iteratePages`, `collectPages`, `PaginationLimitError`,
  `DEFAULT_MAX_PAGES = 100`, stuck-token guard, `AbortSignal`). Used by `core/aws/cleanup.ts`
  (all six list calls; S3 purge capped at 1000 pages), `infra/controller/handler.ts`
  (`ListMicrovms`, `ListSecrets`), `core/status.ts` (`resolveRunId` now lists `runs/` with
  `Delimiter: "/"` and matches exact > suffix > substring), `core/launcher.ts` (`maxConcurrent`
  counts every page), `core/list.ts`, `core/aws/image.ts` (`pruneVersions`), `core/aws/readiness.ts`,
  `core/aws/secrets.ts`, `core/lifecycle-ops.ts` (destroy).
- `emptyAndDeleteS3Bucket` falls back to the unversioned sweep only for `AccessDenied`,
  `NotImplemented`, `MethodNotAllowed`, `UnsupportedOperation`; every other error is rethrown with
  the bucket name and cause.
- Packaging: `scripts/build.ts` bundles `cli/main.ts` with `packages: "external"` and no sourcemap,
  reports `cliBundlePath` in `BuildSummary` and the summary line; `package.json` gains
  `prepublishOnly: npm run check && npm run build`; `core/setup/run.ts` no longer dynamically
  imports `scripts/build.ts` (missing artifacts fail with `ARTIFACTS_MISSING` and a next step).
- IAM: `KmsKeyArn` passed to the image stack by `core/setup/run.ts` and `core/lifecycle-ops.ts`;
  controller statement `KmsControllerBucketAccess` adds `kms:GenerateDataKey*`; `docs/iam.md` §5
  and `05-references.md` document why `secretsmanager:ListSecrets` needs `Resource: "*"`;
  `tests/unit/infra-policies.test.ts` walks every role/policy in both templates (incl. `Fn::If`
  branches) and asserts the `HasKmsKey` condition and statement.
- One default stack name: `DEFAULT_STACK_NAME` lives in `shared/config.ts` and feeds the schema
  default, `core/sync.ts` (re-export) and the wizard's GitHub secret name (`core/setup/steps.ts`).
- Runner `/v1/prompt` accepts `follow_up` as an alias and always echoes `followUp`
  (`runner/api.ts`, `shared/protocol.ts`, `docs/protocol.md`).
- `cloud_agent` steer failure text ends with what to do next, chosen from the run status
  (`extension/tools/cloud-agent.ts`).
- `extractTar` (`core/pi-config.ts`): realpath check of the target and every parent directory,
  refusal to write through an existing symlink (including dangling ones), ustar `prefix` support,
  GNU `L` / PAX `x` headers applied to the next entry, `g` headers skipped, links/devices/FIFOs
  never materialised, returned paths stay relative to the caller's `targetDir`.
- Tests: `tests/unit/paginate.test.ts`, `tests/unit/cli-packaging.test.ts`, `tests/fakes/cfn-template.ts`;
  strengthened `aws-cleanup` (two-page version listing, fallback, rethrow), `controller` (two-page
  `ListSecrets`), `runner-lifecycle` (env reaches the real `git` process: author identity taken from
  env), `pi-config` (prefix, long names, PAX, links, symlinked parent, dangling symlink),
  `setup-run` and `cloud-update-destroy` (parameter keys equal the template's declared parameters).
